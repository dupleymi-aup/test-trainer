# Plan: Fix i18n 404, FormLabel crash, missing translations

## Issue 1: FormLabel crash on register page (quick fix)

**Root cause:** `FormLabel` (line 142) is rendered OUTSIDE the `<Form {...form}>` wrapper (line 169). `FormLabel` calls `useFormContext()` which returns null when no `FormProvider` ancestor exists.

**File:** `src/app/(auth)/register/page.tsx`

**Fix:** Move the account-type selector block (lines 140-167) INSIDE the `<Form {...form}>` wrapper at line 169, right after `<form>` opens. The `FormLabel` on line 142 can stay as-is once it's inside the `FormProvider` tree.

Alternatively, replace `<FormLabel>` with a plain `<Label>` from `@/components/ui/label` (simpler, no form context dependency).

**Recommended:** Move the block inside `<Form>` — keeps semantic consistency with the rest of the form.

## Issue 2: Missing translation keys (quick fix)

**Root cause:** `register/page.tsx` line 158 calls `t("student")` and `t("teacher")` under the `auth` namespace. These keys don't exist in any message file. The `auth` section has `studentDescription` and `teacherDescription` but NOT `student` or `teacher`.

**Files:** `messages/ru.json`, `messages/en.json`, `messages/zh.json`

**Fix:** Add `"student"` and `"teacher"` keys to the `auth` section in all three message files:
- `ru.json`: `"student": "Студент"`, `"teacher": "Преподаватель"`
- `en.json`: `"student": "Student"`, `"teacher": "Teacher"`
- `zh.json`: `"student": "学生"`, `"teacher": "教师"`

## Issue 3: i18n 404 on /en and /zh (structural)

**Root cause:** The app uses `next-intl` with `localePrefix: "as-needed"`, so `/en` and `/zh` are valid URL patterns. But there is NO `src/app/[locale]/` directory — all pages sit directly at `src/app/`. Next.js has no route handler for `/en` or `/zh`, returning 404.

The root layout (`src/app/layout.tsx`) already calls `getLocale()` and wraps children with `NextIntlClientProvider`, but this only works when the locale is resolved from a `[locale]` URL segment.

The custom middleware (`src/middleware.ts`) does NOT integrate `next-intl`'s middleware — no locale detection, no redirect logic.

**Fix:** Move all page routes under `src/app/[locale]/`:

1. **Create `src/app/[locale]/layout.tsx`** — Move the current `src/app/layout.tsx` content here (it already handles locale)
